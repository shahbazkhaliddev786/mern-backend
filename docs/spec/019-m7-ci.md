## Goal

Every push to the backend runs lint, the build and the full test suite, with MongoDB and Atlas local as services, so the safety gate (spec 018) and every database-backed test actually run, not skip. A failure shows on the commit and the PR. The judged evals run on a schedule once API keys are set as repository secrets.

## Context

- **Design:**
  - [`evals.md`](../shopping-agent/evals.md) §11: the safety split runs on every PR and blocks at 100%; the judged suite runs on a schedule within a budget.
  - [`phases.md`](../shopping-agent/phases.md) M7: "GitHub Actions runs the safety split on every PR (blocking at 100%) and the judged suite nightly or on demand, within a token budget."
- **What exists:**
  - **No backend CI** (no `.github/workflows`). The frontend has `ci.yaml`, run on pushes and PRs to `main`; it stays as it is.
  - **Locally**, the backend's checks are `npm run lint`, `npm run build` and `npm test`. The database suites (MongoDB: 8 files including the safety gate; Atlas local: 1) skip without `MONGO_URL` / `ATLAS_URL`.
  - **Judged evals:** `npm run eval:knowledge` (spec 013) needs `ANTHROPIC_API_KEY`, `VOYAGE_API_KEY` and an Atlas database with the knowledge ingested.
- **Found while planning — the backend doesn't install cleanly:**
  - Since the agent dependencies were added (`9e8e9b0`), a plain `npm ci` or `npm install` fails with `ERESOLVE`: `deepeval` 0.9.22 pins `@langchain/core` 1.1.31 as a peer, while the agent packages need ≥ 1.2.14 (follow-ups §16).
  - The lockfile was made with `--legacy-peer-deps`, and `npm ci --legacy-peer-deps` works.
  - **CI can't install without a fix, and neither, most likely, can Vercel,** which runs a plain `npm install`. Backend deploys of this branch would then fail at install. That can't be checked from here (`*.vercel.app` is blocked).

## Scope

**In:**
- **The install fix:** a committed `.npmrc`.
- **The workflow:** `.github/workflows/ci.yml` with a checks job and a judged-evals job.
- **No silent skip:** in CI, the safety gate fails instead of skipping when `MONGO_URL` is missing.
- **Reporting:** the safety report in the job summary and as an artifact.
- **Docs** for the owner's one-time GitHub settings: required check and secrets.

**Out:**
- **The frontend's CI** (it exists).
- **Deploying from CI** (Vercel deploys from Git).
- **Writing the judged suite's goldens** (spec 020); this spec only gives them a place to run.
- **Branch protection itself.** It's a repository setting the owner turns on; documented here.

## Design

**Install fix** — `.npmrc` at the backend root:

```
legacy-peer-deps=true
```

- That's how the lockfile was produced. It makes `npm ci`, `npm install` and Vercel's install all behave the same, with no flags to remember.
- **The trade-off:** npm no longer installs or checks peer dependencies automatically. They're all already explicit in `package.json`.
- The comment in `follow-ups.md` §16 is updated.

**Workflow** — `.github/workflows/ci.yml`:

| Job | When | Steps |
|---|---|---|
| **`checks`** | Every push (all branches), and on demand | Node 22, `npm ci`; `npm run lint`; `npm run build`; `npm test` with the two database services; then `npm run eval:safety` as its own named step, with the report added to the job summary and uploaded as an artifact |
| **`judged-evals`** | Weekly and on demand (open question 3) | Skips with a note unless `ANTHROPIC_API_KEY` and `VOYAGE_API_KEY` secrets exist. Then: Atlas local service → `npm run agent:setup` → `npm run agent:ingest` → `npm run eval:knowledge` (and 020's suites once they exist). Scores go to the job summary |

- **Database services:**
  - `mongo:7` on 27017
  - `mongodb/mongodb-atlas-local:8.0` on 27018, with a health check so the job waits for it
  - The jobs set `MONGO_URL=mongodb://localhost:27017` and `ATLAS_URL=mongodb://localhost:27018/?directConnection=true`.
- **No silent pass:** in CI (`CI=true`), the safety gate fails when `MONGO_URL` is missing. A misconfigured job can't pass by skipping the gate. The check is one line at the top of `redteam.mongo.test.ts`.
- **Concurrency:** a newer push to the same branch cancels the older run.
- **Cost guard:** the judged job only runs on its schedule or when started by hand, never on every push. One run's cost is measured on its first run and recorded here.
- **Secrets the judged job reads:** `ANTHROPIC_API_KEY`, `VOYAGE_API_KEY`. Nothing else is needed: knowledge is ingested into the job's own Atlas local, not production.

**Owner settings** (documented in the spec's results and `phases.md`, done once in GitHub):
- **Branch protection on `main`:** require the `checks` job to pass before merging.
- **Repository secrets** for the judged job: `ANTHROPIC_API_KEY`, `VOYAGE_API_KEY`.

## Acceptance criteria

- [ ] `npm ci` (no flags) succeeds from a clean copy of the repo
- [ ] **The first `checks` run on GitHub is green:**
  - [ ] lint, build, and `npm test` with every database suite running (none skipped for lack of a database)
  - [ ] the safety gate step shows 17 pass and 1 n/a in the job summary
- [ ] A deliberately failing test on a throwaway branch turns the `checks` run red. That shows a failure blocks; the branch is deleted afterwards
- [ ] Without secrets, `judged-evals` ends with a "skipped: no API keys" note, not a failure
- [ ] In CI, the safety gate fails if `MONGO_URL` is missing — test (run locally with `CI=true`)

## Open questions

1. **Fixing the install.**
   - **Recommended:** a committed `.npmrc` with `legacy-peer-deps=true`. It matches how the lockfile was made, and it fixes CI and Vercel alike.
   - **Alternative:** move `deepeval` into its own `evals/package.json`, so the app's install has no conflict. Spec 001 decided against that, keeping deepeval in the backend.
2. **When `checks` runs.**
   - **Recommended:** every push to any branch, plus on demand. Checks then show on PRs too (they run on the PR's commits), and this branch gets checked right away.
   - **Alternative:** only PRs to `main` and pushes to `main`, like the frontend.
3. **How often the judged evals run.**
   - **Recommended:** weekly and on demand at first. Every run spends real tokens: the agent model per question, plus an Opus judge per metric. Move to nightly once a run's cost is known and agreed.
   - `evals.md` says nightly; this starts lower until the cost is measured.
